# 04: shell 拦截 — 覆盖删除与建目录

**What to build:** 开发者最在意的场景是「agent 把不该删的东西删了」。pi 没有 delete 工具、也没有 mkdir 工具，删除、移动、建目录只能经由 shell 命令落到文件系统，所以只盯 `write`/`edit` 的话，这个场景一个都覆盖不到。这个 ticket 让 `rm -rf src/`、`mv`、`mkdir` 这类命令走同一套约束判断。同时，`npm test`、`git status`、构建命令这些纯读操作必须完全不产生请求——shell 调用里绝大多数是这类，每次都送检会既慢又费，开发者会直接把插件关掉。Windows 上用 `powershell` 的人得到同等对待。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 在 `tool_call` 上拦截 `bash` 与 `powershell`
- [ ] 本地正则预筛：命中可能改动文件系统的迹象才送检（常见改动命令、原地流编辑、输出重定向）
- [ ] 预筛刻意从宽：有歧义时倾向送检，让模型而非正则做最终判断
- [ ] 送检时以命令原文作为变更内容，超长截断并标注
- [ ] 预筛未命中的命令完全不构造请求、不调用 API
- [ ] `powershell` 与 `bash` 走同一套规则，不是空实现
- [ ] 预筛常开，不提供配置项
- [ ] 测试覆盖：删除类命令送检、移动/建目录送检、原地流编辑送检、输出重定向送检、只读命令不送检（无请求）、`powershell` 与 `bash` 行为一致
