# 02: 约束文件发现

**What to build:** 开发者把约束写在 `docs/constraints.md`（他的 `AGENTS.md` 已经指向那里），守卫照样生效。文件名写成 `CONSTRAINTS.md` 也认。如果他两个位置都放了文件，两份规则都生效——而不是其中一份被静默吞掉。守卫报出的每条违规都能说清它来自哪个文件。他在会话进行中收紧了某条规则，下一次工具调用就按新规则判，不用重启 pi。项目里没有约束文件时，守卫完全静默、一次 API 都不调。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 除项目根目录外，同时在 `docs/` 下查找约束文件
- [ ] 文件名大小写不敏感匹配 `constraints.md`：通过列目录比对，而非逐个猜测固定拼写
- [ ] 两个位置都存在时，两份文件都读取，条目拼接成一份清单（合并而非覆盖）
- [ ] 每个条目记录其来源文件，可被后续消费
- [ ] 每次检查前对候选文件 `stat`，修改时间变化则重新读取并重新切分
- [ ] 两处都没有约束文件时，不构造请求、不调用 API
- [ ] 测试覆盖：仅根目录、仅 `docs/`、两处都有且合并且来源正确、大写文件名、完全没有文件（无请求）、会话中途文件被改（按新内容判）
